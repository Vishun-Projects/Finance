Micro-interactions guide and glassmorphism demo for developers

Micro-interactions developers always skip
1. Hover lift + active press — buttons feel dead without it Most skipped
Devs add hover bg-change and call it done. The eye doesn't feel it. You need translateY(-1px) on hover and scale(.97) on active. Combined they give the illusion of physical depth — button lifts toward you, then presses in. Takes 3 lines of CSS.
2. Skeleton screens instead of spinners Always missing
A spinner says "wait." A skeleton says "here's where your content will be." Skeletons reduce perceived load time by 15–20% in studies because the brain starts placing content before it arrives. Use a shimmer animation — not a pulse.
3. Focus rings — accessibility AND feel Always skipped
Devs do outline: none because the default browser ring is ugly. Then they never replace it. Every input needs a custom focus ring: box-shadow: 0 0 0 3px rgba(0,0,0,.08). Subtle for sighted users, essential for keyboard users.
4. Checkboxes and toggles with spring animation Always missing
Browser default checkboxes feel like 2005. Custom ones with cubic-bezier(.34,1.56,.64,1) — a spring curve that overshoots slightly — feel alive. The toggle thumb should bounce just past its target, then settle back. That overshoot is what makes iOS feel premium.

5. Tooltips that animate in — not instant pop Skipped
Tooltips that snap instantly feel like debug overlays. They should scale in from the anchor point: transform: scale(.9) → scale(1) with opacity 0 → 1 over 120ms. Short enough to not feel slow. Long enough to feel intentional.

6. Copy button with confirmation state Often missing
A copy button that does nothing visually after click makes users click it 3 times. The button should transition to "Copied ✓" for 1.5s then revert. Zero toast needed — the confirmation lives inline where the action happened.

7. Animating number changes — not just hard-swapping values Premium feel
When a metric card updates — say from 4,978 to 5,012 — devs just swap the innerHTML. The number teleports. Counting up/down over 400–600ms makes the change feel real, not glitchy. Especially powerful for your ARCP metric cards updating while loading.

8. Cursor changes — pointer vs default vs not-allowed Always wrong
Disabled buttons should have cursor: not-allowed, not cursor: default. Draggable elements need cursor: grab / grabbing. Clickable non-button elements need cursor: pointer. Resizable columns need cursor: col-resize. These are invisible affordances — users feel them before they see them.

Glassmorphism — done right vs done wrong
iPhone-style glassmorphism has 4 ingredients: a colourful blurred background, a semi-transparent frosted card, a subtle white border, and white text. Remove any one of them and it falls apart. The most common mistake is applying blur to a white/grey background — glass needs colour behind it to look like glass.

The CSS — 4 lines that matter
/* 1. The card */ .glass-card { background: rgba(255, 255, 255, 0.12); /* low alpha */ backdrop-filter: blur(12px); /* the frost */ -webkit-backdrop-filter: blur(12px); /* Safari */ border: 1px solid rgba(255, 255, 255, 0.25); /* glass edge */ border-radius: 16px; } /* 2. Background MUST have colour + blur source */ .glass-bg { background: linear-gradient(135deg, #667eea, #764ba2, #f093fb); filter: blur(0); /* bg itself stays sharp */ } /* 3. Floating colour blobs for depth */ .blob { border-radius: 50%; filter: blur(40px); /* blobs blur, not the bg */ opacity: 0.6; }
The rules — where glass works and where it breaks
Works

Cards over rich colourful backgrounds. Modals and dropdowns over blurred page content. Navigation bars over photos. Notification toasts. Metric cards over gradient dashboards.

Breaks

Glass over a white background (nothing to blur). Glass over grey surfaces (looks dirty, not frosted). Too many glass layers stacked (blur-on-blur = muddy). Text-heavy content (contrast suffers).

Performance: backdrop-filter: blur() is GPU-intensive. Don't use it on more than 3–4 elements per page. On a data-heavy page like yours, keep glass for summary cards and modals only — not every table row.
The nuances list — things no tutorial mentions
Transition only the properties you need — transition: all .2s causes layout reflows. Write transition: background .15s, transform .15s, opacity .15s explicitly. It's faster and avoids animating width/height accidentally.
Don't animate layout properties — never transition width, height, margin, or padding. These trigger reflow on every frame. Use transform: scaleX() instead of width, transform: translateY() instead of margin-top.
System font stack for numbers — font-variant-numeric: tabular-nums on every column of numbers. Without it, digits have different widths and columns wobble as data updates.
Prefers-reduced-motion — wrap all animations in @media (prefers-reduced-motion: no-preference). About 30% of users have vestibular disorders or motion sensitivity. Animations that feel premium to most feel nauseating to them.
Line-height on dense tables — most devs leave line-height at 1.5 everywhere. Table rows need 1.3–1.4. Too much line-height in a row makes numbers hard to align vertically and wastes precious row height.
Text selection colour — ::selection { background: rgba(0,0,0,.1) }. Default blue selection on black text in a dark-themed tool looks jarring. One line, matches your design language.
Scroll anchoring on data updates — when new rows load or filters apply, the page shouldn't jump. Use overflow-anchor: auto and be careful about DOM insertions above the scroll position.
Don't block the UI thread during filter/sort — if your filter runs synchronously on 5,000 rows, it freezes the input for 80–200ms. Debounce search inputs by 200–300ms. For heavy operations, use a Web Worker or requestIdleCallback so the UI stays responsive while computing.
